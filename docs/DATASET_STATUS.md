| licensing | project-owned frames; Open Images CC BY 4.0, attribution required |

**Recovery procedure.** The manifest is the authority. To verify a copy, re-run
`scripts/dataset_manifest.py` against it with `--out` pointing elsewhere and
compare image and label hashes to the manifest beside the data. To rebuild:
`av7_merged` holds the merged human and auto labels,
`scripts/reindex_labels.py` maps label indices **by name** onto the trained
vocabulary, and the splitter produces `av7_split`; the Open Images portion
re-downloads. The manifest is 520 KB of per-file hashes and is not committed —
`datasets/` is a directory-level gitignore that a negation pattern cannot reach
into — so it lives beside the data and is regenerated by one command.

are listed because a large count can also mean an annotation pass silently

**Duplicates and leakage: none in the split datasets.** Checked by MD5 over image
content:

```
av7_split val inside av7_split train : 0
av6_split val inside av6_split train : 0
av7_split val inside av6_split train : 0      <- AV-6 never saw the eval set
av7_split val identical to av6_split val : 336 of 336
```

The last line is what makes a fair comparison possible: AV-6 and AV-7 share the
same validation images, and neither trained on them.

### Hashes are not enough, so the split was re-checked by source

File hashes miss the leakage that matters here. These images are video frames:
frame 00699 and frame 00700 of one walkthrough are different bytes and almost
identical content, so a hash check reports "no leakage" while the model is
effectively validated on its own training data. The filenames carry the source
recording (`<videoid>_<title>_<frame>.jpg`), so the real question is answerable,
and `scripts/dataset_manifest.py` now asks it:

```
train  1685 images  1157 sources
val     336 images   252 sources
shared sources between train and val : 0
identical images between train and val : 0
```

**Zero shared source recordings.** `av7_split` is isolated at the recording
level, not merely at the file level, so the numbers in
[MODEL_EVALUATION.md](MODEL_EVALUATION.md) survive the stronger test. Three
walkthroughs dominate the training side (302 frames from a Dubai mall tour, 126
from one session, 103 from a hospital tour) and none of them appears in val.

**Leakage policy, from here on:** splits are isolated by source recording,
session, environment and physical location — not by file hash. One video goes
entirely to one split. `scripts/dataset_manifest.py` exits non-zero if that is
violated, so it can gate a pipeline.

## Gap analysis against real product scenarios

§18 of the brief asks what the dataset covers against what the product must
handle, and — importantly — which technology each gap actually needs. Forcing
all of it into one detector is how a declared class ends up unlearnable.

Box counts are `av7_split` train instances.

### People

| scenario | right technology | boxes | state |
|---|---|---|---|
| person | detection | 2,533 | **covered**, best-supported class |
| approaching person | detection + tracking | — | partial — approach is derived from tracking, never measured |
| groups / crowds | detection | — | **gap** — crowd frames not separately annotated |
| partial occlusion | detection | — | **gap** — not labelled as a condition, so recall under occlusion is unknown |

### Indoor

| scenario | right technology | boxes | state |
|---|---|---|---|
| chair | detection | 277 | thin; recall 0.357 |
| table | detection | 75 | **near-unlearnable**; recall 0.059 |
| door | detection | 604 | covered by volume, recall still 0.285 |
| stairs up | detection | 399 | recall 0.444, the best hazard class |
| stairs down | detection | 60 | **unvalidated** (R-005) |
| pole | detection | 0 | **retired** — declared once, no data |
| bin | detection | 730 | covered; recall 0.800 |
| corridor obstacle | detection | — | **gap** — not a class |
| glass door | detection is the wrong tool | 0 | **gap** — a transparent surface has no visual extent to box; needs depth or reflection cues |

### Mall / building

Escalator, elevator, entrance, signage, temporary display, queue barrier: **all
absent.** Two of these are not detection problems — "entrance" and most signage
are **OCR plus spatial association**, which the text pipeline already does, and
wiring that to the world model is cheaper than annotating a class.

### Outdoor

| scenario | right technology | boxes | state |
|---|---|---|---|
| car, bus, truck, motorcycle, bicycle | detection | 0 in project data | **asserted via COCO's vocabulary, never measured** |
| pole, bollard, barrier | detection | 0 | **gap** |
| bench | detection | 0 (COCO has it) | unmeasured |
| sidewalk obstacle | detection | 0 | **gap** |

`av7_split` is indoor footage. Every outdoor claim this project makes rests on
COCO's class list rather than on a measurement, which is the single largest
evidence gap in the product.

### Walking surface — a different problem entirely

Curb, ramp, sidewalk, crosswalk, walkable and non-walkable region: **none
covered, and none of them is a detection problem.** A kerb is a boundary and a
walkable path is a region; a bounding box around either says nothing useful.
These need **semantic segmentation**, and crosswalks additionally need **map
data**, which is navigation rather than perception. Annotating them as boxes
would produce a class that trains to a plausible mAP and helps nobody.

## `assistive_test_v1` — design for a locked test set

The project has no test set. Every figure it reports is a validation figure, and
`av7_split/val` was used for model selection, so it is validation data and must
be called that (§12).

**Purpose.** One set, held back, that the training loop never sees. Not used for
model selection, threshold tuning, architecture choice, early stopping or
hyperparameters. Read at most once per promotion decision.

**Composition**, sized for the gaps above rather than mirroring the training
distribution:

| part | target | source |
|---|---|---|
| indoor hazards | ~250 images, every class, ≥30 instances of each | **whole recordings held back** from the existing walkthrough pool |
| outdoor / vehicles | ~250 images | **new capture required** — parked and moving vehicles, bicycles, buses, distant and partly occluded objects, low light, glare, crowds |
| stairs, both directions | ~100 images | **new capture required** — shot from the top of a staircase, which Open Images does not contain |
| text in situ | ~100 images | door signs, room numbers, EXIT signage, at realistic angles |

**Isolation rule.** Selected by **whole source recording**, never by sampling
frames. A recording that contributes to the test set contributes to nothing
else. This is the policy above, applied at the point it matters most.

**Capture safety.** Outdoor footage is filmed from pavements and other
controlled positions. No live road-crossing experiments (§20).

**Not built.** The indoor part can be carved from existing recordings today; the
outdoor and stairs parts require filming that nobody has done, and public
sources do not supply either.

## Open work

1. **No locked test set.** `assistive_test_v1` is designed above and not built.
   Until it exists, every number the project reports is a validation number and
   is labelled as one.
2. **Outdoor and vehicle capability is unmeasured.** The one safety claim with
   no evidence behind it.
3. `stairs_down` needs footage shot from the top of a staircase. Open Images
   photographs staircases from below, so this cannot be sourced publicly.
4. `table` at 75 train instances is close to unlearnable; measured recall 0.059.
5. **Walking surfaces need segmentation, not more boxes.** No segmentation
   capability exists anywhere in the project.
6. Glass doors need depth or reflection cues; detection is the wrong tool.
